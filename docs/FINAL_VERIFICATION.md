최초 실행에서는 명확한 주문을 LLM이 메뉴 선택으로 해석하는 경우와 브라우니 대안 ID 누락을 확인했습니다. `api/dialogue.py`는 명확한 주문·온도 답과 추가 주문·수량 변경에 기존 규칙을 재사용하고, `api/index.py`는 RAG 후보가 비었을 때 팀 대안 CSV를 사용합니다. 시험 코드의 가격 기대값도 실제 카탈로그 기준으로 바로잡았습니다. 수정 후 위 다섯 흐름이 통과했습니다.

현재 별도 회귀 검증: Mock API 42건, RAG 단위 3건, 주문·상태 55건 통과, 타입 검사와 빌드 통과. 실제 흐름 시험은 `tests/live-flow.test.ts`의 5건 통과입니다. 이 파일은 기본 `npm test`에서 건너뛰며 아래 명령으로만 실제 API를 호출합니다. 외부 API 사용료가 발생할 수 있습니다.

## 직접 화면에서 확인할 체크리스트

기존 8000·3000번 서버가 실행 중이면 먼저 종료합니다. 저장된 인덱스는 재생성하지 않습니다. 프로젝트 루트에서 터미널 두 개를 사용합니다.

```bash
source .venv/bin/activate
KIOSK_MODE=live RAG_REBUILD_INDEX=0 npm run api
```

```bash
npm run dev
```

접속 주소: `http://localhost:3000`. API 키 없이 Mock 화면을 보려면 첫 명령을 `KIOSK_MODE=mock npm run api`로 바꿉니다. Mock의 정보 답변·근거는 시험용입니다.

- [ ] 새 주문에서 `라떼 하나요` → `아이스요, 치즈케이크도 주세요`: 라떼 ICE 1개·케이크 1개·7,600원, 중복 없음.
- [ ] 새 주문에서 `라떼 하나랑 치즈케이크 하나요` → `카페인은요?` → `아이스요`: 정보 답변 뒤 온도를 다시 묻고 각 1개·7,600원.
- [ ] 새 주문에서 `브라우니 주세요` → 초코무스케이크 대안 버튼: 선택 전 0개, 선택 뒤 1개·4,200원.
- [ ] 새 주문에서 `아이스 아메리카노 두 잔이랑 치즈케이크 하나 주세요` → `아메리카노에 샷 하나 추가해 주세요` → `아메리카노 세 잔으로 바꿔 주세요` → `아메리카노 샷 추가는 빼 주세요`: 3잔·케이크 1개·11,700원.
- [ ] 새 주문에서 `아이스 아메리카노 하나 주세요` → `그게 다예요` → `포장이요` → `네, 그런데 치즈케이크도 추가요` → `네` → `카드로 할게요` → 결제 버튼: 변경된 6,700원을 다시 확인하고 모의 주문번호 표시.

화면의 말풍선·버튼·메뉴 카드·주문 내역·완료 창까지 눈으로 확인한 결과는 아직 없습니다. 위 체크리스트는 **실행 방법**이며 완료 기록이 아닙니다.

## 팀 인계에서 남은 확인

- RAG 담당: `카페인은요?` 답변은 반환됐지만 근거 ID가 비어 있습니다. 브라우니의 실제 RAG 대안 후보도 비어 팀 CSV 규칙으로 대체됐습니다. 검색·근거·추천 내부 품질은 별도 확인이 필요합니다.
- 화면·주문 담당: 위 브라우저 체크리스트와 완료 창의 모의 결제 표시를 직접 시연·확인해야 합니다.
- HTI·발표 담당: 저장소에는 `HTI_키오스크.xlsx` 원본과 팀 발표 자료·시연 캡처가 없습니다. HTI 원본은 별도 보관 중이므로 최종 제출·발표 묶음에 포함할지 팀에서 확인해야 합니다. 발표에는 실제 RAG 근거·대안 제한과 브라우저 미검증 상태를 그대로 표시합니다.
